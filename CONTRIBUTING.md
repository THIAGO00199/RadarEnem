# Contribuir com a ATENA

Contribuições de estudantes, professores e desenvolvedores são bem-vindas.

## Relatar um problema

Abra uma issue com o caminho da ferramenta, o que você tentou fazer, o resultado esperado, o resultado observado e o navegador. Uma captura ajuda, mas remova nomes, redações pessoais, notas e outros dados de estudantes antes de publicar. Nunca anexe um backup pessoal a uma issue pública.

## Código

1. Crie uma branch e reproduza o problema antes de alterar o comportamento.
2. Preserve os formatos de backup, as chaves de progresso e o suporte ao endereço com `/RadarEnem/`.
3. Faça a menor alteração que conclua o fluxo. Botões devem executar uma ação real ou explicar claramente o estado indisponível.
4. Execute o build, TypeScript e os testes pertinentes descritos no README. Mudanças em cache, navegação ou estado exigem verificar o fluxo offline.
5. Descreva no pull request o problema, o comportamento final, a validação e os limites conhecidos.

Não envie chaves, arquivos de ambiente, dados de estudantes nem dependências com serviços pagos obrigatórios. Animações precisam respeitar movimento reduzido e permitir leitura imediata. Não esconda o conteúdo essencial atrás de efeitos de entrada.

## Conteúdo pedagógico

Uma lição precisa de objetivo, explicação, questão com alternativa correta e resolução comentada. Identifique material autoral como treino. Referências devem apontar para a instituição ou publicação original e trazer contexto suficiente para o estudante compreender o argumento.

Não apresente o Radar como previsão do tema da prova, um diagnóstico local como nota oficial, ou um simulado autoral como TRI. Uma referência literária, científica ou histórica só deve entrar depois de conferida. PDFs externos permanecem na origem; não reenvie material protegido sem autorização.
